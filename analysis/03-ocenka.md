# 3. Оценка

Нормативный контракт — `docs/SCORING_SPEC.md` релиза 1.0 в репозитории организаторов. Ниже та же арифметика, разложенная по решениям, которые она поощряет и наказывает.

## Итог

Каждый компонент лежит на отрезке `[0, 1]`, единица — идеал.

```text
S_total = 0.35*S_state + 0.30*S_queue + 0.15*S_physics + 0.20*S_ODME
```

Отсутствующий выход задачи даёт 0, а не пропуск в среднем. Пустая сдача даёт 0.0000, а не маленькое положительное число. Коридор без оцениваемых ячеек даёт 0, а не 1.

Неполный или некорректный набор строк отдельной задачи обнуляет всю эту задачу. Для Physics это означает: нет годного State — нет и Physics, то есть сразу пропадают 0.50 итогового веса.

## State

По каждому режиму `r` из `{R1, R2, R3}`:

```text
S_speed(r) = max(0, 1 - RMSE_speed(r) / 25)          # км/ч
S_flow(r)  = max(0, 1 - RMSE_flow_per_lane(r) / 600) # авт/ч/полоса
S_state(r) = 0.54*S_speed(r) + 0.46*S_flow(r)
S_state    = среднее по трём режимам
```

Поток перед RMSE делится на число полос станции из `fd_parameters.csv`, и у сдачи, и у истины. По полному потоку связи шкала 600 была примерно в пять раз жёстче шкалы 25 км/ч и делала коридоры несравнимыми из‑за числа полос. У одной модели фиксированного качества `S_flow` гулял от 0.0086 до 0.3255 по десяти коридорам. После перехода на полосу разброс `S_state` сжался с 0.158 до 0.020.

Пропавшая строка оценивается как нулевой прогноз и остаётся в знаменателе RMSE. Частичная сдача формально валидна и сама себя штрафует.

Практический смысл шкал: 25 км/ч RMSE по скорости или 600 авт/ч/полоса RMSE по потоку обнуляют соответствующую половину режима. Ошибка заметно меньше этих порогов ещё даёт высокий `S_state`. Исторический профиль уже сидит около 0.69, значит дешёвые баллы State частично забраны, а оставшийся запас — в пространственно-временном контексте и в режиме R3, где вырезана половина пригодных ячеек.

## Queue

На каждое окно:

```text
IoU = |предсказанные И истинные| / |предсказанные ИЛИ истинные|
```

Окно, где очереди правда нет и она не предсказана, даёт 1. В этом бенчмарке такие окна в оценку не попадают: оба типа окон содержат очередь в горизонте.

`queue_onset` и `queue_ongoing` имеют равный вес. Внутри коридора и сплита каждого типа по пять окон. Окна и условия усредняются с равными весами.

`queue_pred` обязан быть 0 или 1. Пропавшая строка читается как 0. Шаблон для удобства перечисляет окна нескольких сплитов; оценщик берёт сплит, который ему передали, и игнорирует остальные.

IoU наказывает и пропуск очереди, и лишнюю очередь. Повтор состояния на `T-5` на все шесть шагов — это сильная база для `queue_ongoing` и слабая для `queue_onset`, где в истории очереди ещё нет. Именно onset несёт основной запас относительно персистентности.

Метки скрыты на всех сплитах. Подбирать порог по публичному рейтингу можно, но каждый заход тратит лимит отправок, а private содержит другие инциденты.

## Physics

```text
S_physics = (1/3)*S_FD + (2/3)*S_LWR
```

`S_FD` проверяет, могут ли сданные скорость и поток вообще сосуществовать на дороге. Это отсев невозможного, а не ранжирование хорошего. Правдоподобный ответ его проходит. Считается на полосу:

```text
q_lane = q_total / lanes
k_lane = k_total / lanes
capacity_lane = capacity / lanes
```

Нулевой поток при нулевой плотности лежит на диаграмме и выпадает из отношения. Раньше «опустошение» сдачи поднимало `S_FD`. Теперь панель и режим, где больше пятой части сданных ячеек ниже 50 авт/ч, получают `S_FD = 0`. В релизе коридоры загружены круглые сутки и до этого пола не опускаются. Честный ответ порог не задевает.

`S_LWR` — основная разделяющая часть. Считается в единицах полного потока на пятиминутных переходах:

```text
S_LWR = max(0, 1 - sum|residual| / sum|rhs|)
```

Балл монотонно падает с ростом нарушения баланса и уходит в ноль, если реконструкция разгладила затор. Покрытие переходов зависит от режима наблюдаемости рамп. В этом релизе все десять коридоров — режим A: покрытие рамп 0.7560, валидных ячеек достаточно. Порог режима A — покрытие не ниже 0.75 и не меньше 100 000 валидных ячеек. Запас над границей A/B всего около 0.006, поэтому таблица режимов заморожена в `config/task3_lwr_modes.json` и не пересчитывается при каждой оценке.

Диагностический `S_qkv` в выход оценщика попадает, но в балл не входит: при `k = q/v` равенство `q = k*v` выполняется тождественно.

Практический потолок Physics около 0.96 даже у точного State: остаток баланса сравнивается с шумными наблюдениями. Потолок общий для всех. В таблице базовых решений идеальный ответ имеет `S_physics = 0.9636`.

Локальная цифра около 0.33 не используется для сравнения методов.

## ODME

```text
S_od   = max(0, 1 - sum|fhat - f*| / max(sum f*, eps))
S_link = max(0, 1 - sum|A*fhat - c| / max(sum c, eps))
S_dev  = exp(-|Dhat/Dstar - 1|)
S_attr = max(0, 1 - 0.5*L1(a_hat, a_star))

S_ODME = 0.45*S_od + 0.25*S_link + 0.15*S_dev + 0.15*S_attr
```

Обозначения:

- `f*` — эталонный поток по путям, скрыт;
- `fhat` — сдача;
- `A` — опубликованная матрица инцидентности путь–связь;
- `c` — опубликованные счётчики;
- `b` — опубликованный слабый априор;
- `Dhat = sum|fhat - b|`, `Dstar = sum|f* - b|`;
- `a` — нормированное распределение притяжения по зонам назначения.

`S_dev` закрывает два вырожденных ответа: сдать априор как есть и идеально посадить счётчики диким спросом. `S_od` — почти половина задачи и локально неизвестен. `S_link` — единственная четверть, которую можно стеречь у себя.

Невалидные идентификаторы, чужие зоны, дубли или пропуски путей, отрицательные или неконечные потоки портят затронутый коридор.

## Сдача на Kaggle

Локально удобнее три файла. На платформу уходит один, после склейки:

```text
python src/merge_submissions.py \
  --state state_submission.csv \
  --queue queue_submission.csv \
  --odme  path_flow_submission.csv \
  --key   submission_key.csv \
  --output submission.csv
```

Колонки State: `panel, timestamp, station_id, link_id, mask_regime, speed_kmh, flow_vph`.

Колонки Queue: `window_id, timestamp, link_id, queue_pred`.

Колонки ODME: `panel, departure_time, path_id, origin_zone, destination_zone, path_flow`.

Kaggle не принимает файл с пустой ячейкой. Идентификаторы панелей, связей, станций, путей и зон не переименовываются. Записи рамп из сетевых файлов не удаляются. Значения из файлов, которые выданы только организаторам, не сдаются.

## Что в релиз не входит

Скрытая истина, метки private, полные счётчики private, `queue_true`, граничные потоки организатора и приватная конфигурация оценщика. В публичном пакете есть наблюдения, сеть, шаблоны и код базовых решений.
