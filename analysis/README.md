# Аналитический пакет: TrafficFlowBench 2026

Дата разбора: 4 ноября 2026.

Пакет фиксирует постановку соревнования [2026 IEEE Big Data — Traffic Flow Bench](https://www.kaggle.com/competitions/2026-ieee-big-data-traffic-flow-bench/overview) так, чтобы по нему можно было планировать решение, не перечитывая разрозненные страницы.

Страница Kaggle в момент разбора отвечала ошибкой лимита запросов. Формулы, схемы данных и базовые баллы взяты из открытого репозитория организаторов [jacky850/trafficflowbench-public](https://github.com/jacky850/trafficflowbench-public), релиз 1.0 от 3 сентября 2026. Сроки, призы и допуск сверены со страницей [IEEE Big Data Cup 2026](https://bigdataieee.org/BigData2026/cup/) и открытым пересказом правил. Где источники расходятся, это написано прямо, а не сглажено.

## Короткий вывод

Нужен один CSV по шаблону `sample_submission.csv`. В нём три блока строк: восстановление скорости и потока (State), бинарный прогноз очереди на 30 минут (Queue) и потоки по путям (ODME). Физическая согласованность (Physics) отдельным файлом не сдаётся: её считают по уже сданному State.

Итоговый балл:

```text
S_total = 0.35*S_state + 0.30*S_queue + 0.15*S_physics + 0.20*S_ODME
```

Опубликованный наивный набор на validation даёт около **0.5534**. Потолок полного ответа около **0.9945**, потому что Physics даже у точного State не доходит до 1 из‑за шума измерений.

Данные синтетические. Внешний архив реальных детекторов к ним не присоединяется. Публичный рейтинг и финальный рейтинг считаются по разным месяцам с разным набором инцидентов, поэтому подгонка под validation не переносится на private.
